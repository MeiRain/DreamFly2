# Flash 参数保存

[返回项目首页](../README.md) · [文档索引](README.md)

飞控参数管理集中在 `Application/flight.c/.h`，底层读写位于 `Core/Src/flash.c`。当前只保存六轴、九轴姿态解算的四个 KP/KI 增益；电机控制 PID、校准值和无线配置尚未接入保存。

## 预留参数区

编辑飞控工程的 [`STM32F411xx_FLASH.ld`](../firmware/dreamfly2_flight/STM32F411xx_FLASH.ld)，在 `MEMORY` 中找到：

```ld
FLASH (rx) : ORIGIN = 0x8000000, LENGTH = 512K
```

改为：

```ld
FLASH (rx) : ORIGIN = 0x08000000, LENGTH = 384K
```

只修改 Flash 长度，RAM 保持不变。此地址两种写法等价。

| 区域 | 地址 | 大小 |
|---|---|---|
| 程序区 | `0x08000000`～`0x0805FFFF` | 384 KB |
| 参数区，扇区 7 | `0x08060000`～`0x0807FFFF` | 128 KB |

再编辑飞控 `CMakeLists.txt`，在 `target_sources(${CMAKE_PROJECT_NAME} PRIVATE ...)` 的源文件列表中加入：

```cmake
Core/Src/flash.c
```

参数实现已经放在现有 `Application/flight.c`，无需添加独立 `paramsave.c`。完成上述两处修改后重新构建。保存接口还会检查当前程序加载映像的末地址，发现进入参数区则拒绝保存；此检查不能替代链接脚本预留。

## 加载和默认值

`flight_init()` 在初始化姿态解算前自动调用 `flight_load_params()`：

- 标识、版本、长度、CRC32 和数值范围全部有效：使用保存的参数，返回 `true`。
- 没有有效记录：使用 `flight.c` 中的 `s_default_params`，返回 `false`，不自动擦写 Flash。
- 初始化结束后再次调用加载接口会被拒绝，参数保持不变。

选中的参数先放入 RAM，再交给姿态算法使用，解算期间不会反复读取 Flash。

修改源码默认值不会覆盖已有的有效 Flash 记录。匿名上位机现已接入读取、修改、恢复默认和保存命令，操作见 [在线调参](ano_parameters.md)。恢复默认仅修改 RAM；执行保存后才覆盖 Flash。修改参数由传感器任务同步更新 RAM 和算法增益。

## 现在如何保存

当前保存入口为：

```c
bool saved = flight_save_params();
```

由运行中的任务在明确的保存事件下调用一次，不能从中断调用，也不能放进周期循环反复调用。匿名上位机的保存子命令 `0xE0 / 0x10 / 0x00AB` 已接入此接口，不会随修改参数自动保存。

保存要求初始化已完成、飞控已上锁、没有待应用的参数修改、参数合法且程序未占用参数区。保存期间保持电机输出为 0，并暂停任务调度，避免另一个任务中途解锁。通信和采样会暂停，因此只能停桨后操作。

若 Flash 中已有完全相同的记录，直接返回成功；否则擦除扇区 7、写入当前 RAM 参数并由底层比对：

- `true`：写入和比对成功。
- `false`：状态不允许、数据不合法、程序区重叠或底层操作失败，RAM 参数保留。

## 板级验证

2026-10-28 已通过 UART2 匿名 V8 报文完成实机验证：在线将六轴 KP 从 0.8 改为 0.801，回读并保存后，由用户完全断电重启，读回仍为 0.801，证明启动加载了保存值。测试结束已恢复全部原参数并重新保存成功。完整记录见 [在线调参](ano_parameters.md#uart2-实机记录2026-10-28)。

匿名上位机界面、WiFi 透传和恢复默认命令尚未实测。后续改参仍应先回读确认，再保存，并按需重启验证。

保存不是启动初始化的一部分，不要把保存调用放进每次上电的初始化流程。

## 记录格式与限制

一条记录共 32 字节：标识、版本、参数长度、四个浮点增益及 CRC32。参数字段为 `attitude_6axis_kp`、`attitude_6axis_ki`、`attitude_9axis_kp`、`attitude_9axis_ki`。

第一版使用单扇区整块保存，保存时断电可能使记录失效，下次启动回退默认值。烧录时是否保留参数取决于擦除范围，整片擦除会清空参数区。当前没有双备份或掉电原子更新。
