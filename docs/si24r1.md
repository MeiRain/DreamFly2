# SI24R1 驱动与通信流程

## 当前配置前提

当前驱动文件已从旧版标准库占位代码改为 HAL SPI2 实现。尚未接入任务，也未编译或实机验证。

检查现有生成文件时发现：还没有 `spi.c`、`spi.h` 和 `hspi2`；PB12 配成了下降沿事件，PA8/PB2 未初始化。仅指定 SPI 引脚复用不等于启用了 SPI2 外设。请在 CubeMX 中配置并重新生成代码：

| 项目 | 配置 |
|---|---|
| SPI2 模式 | Full-Duplex Master |
| 数据格式 | 8 Bits、MSB First |
| CPOL / CPHA | Low / 1 Edge，即 SPI Mode 0 |
| NSS | Software，PB12 由 GPIO 控制，不能选硬件 NSS |
| Baud Rate Prescaler | 8；当前 APB1 为 50 MHz，对应 SPI SCK 为 6.25 MHz |
| TI Mode / CRC Calculation | Disabled / Disabled；无线 CRC 由 SI24R1 自己处理 |
| PB13 / PB14 / PB15 | SPI2 SCK / MISO / MOSI |
| PB12 CSN | GPIO_Output，推挽，无上下拉，初始 High；取消原来的 EXTI Event |
| PA8 CE | GPIO_Output，推挽，无上下拉，初始 Low |
| PB2 IRQ | 第一版设 GPIO_Input、Pull-up；后续需要时改下降沿 EXTI |
| SPI DMA / SPI IRQ | 第一版无需开启 |

当前驱动不读取 IRQ 引脚，而是在链路任务中查询状态寄存器和 FIFO。如果以后改为 IRQ 通知，ISR 只通知任务，仍由任务调用 SPI 读写，并在处理通知后持续检查 FIFO，不能只读一包。

生成工程后，确认 `MX_SPI2_Init()` 在启动任务前执行，HAL SPI 驱动加入构建。现有工程按外设分别生成 `.c/.h`，本驱动依赖其 `spi.h`。

手动在根 CMake 的 `target_sources()` 中添加：

```cmake

```

在 `target_include_directories()` 中添加 `Components/Si24R1`；`Common` 已存在。

## 无线参数

两端必须使用相同信道、地址、无线速率及 CRC/动态载荷配置。驱动目前沿用旧工程的 5 字节地址 `34 43 10 10 FF`、信道 `0x48`、RF_SETUP `0x0F`（2 Mbps），开启 pipe 0、CRC16、自动应答和 ACK Payload。自动重试延时 750 us、最多重发 10 次。

这些是固定地址通信参数，尚无配对功能。SPI 的 6.25 MHz 是 MCU 与无线芯片之间的总线时钟，2 Mbps 是无线速率。

飞控使用 SPI2、PA8 CE、PB12 CSN；遥控器硬件不同，移植时需要把驱动文件顶部的 SPI 句柄及 CE/CSN 映射改为遥控器的实际资源，其余通信逻辑相同。

## 通信顺序

1. 飞控调用 `si24r1_init(SI24R1_MODE_RX)`，保持接收角色。
2. 飞控用 `rcprotocol_pack_status()` 准备状态帧，再调用 `si24r1_write_ack_payload()` 预装回传数据。
3. 遥控器调用 `si24r1_init(SI24R1_MODE_TX)`，保持主动发送角色。
4. 遥控器用 `rcprotocol_pack_control()` 打包摇杆和按键，调用 `si24r1_send()` 启动发送；返回 true 仅表示成功启动。
5. 飞控无线芯片收到并通过硬件 CRC 后，自动发送 ACK；若预装了状态数据，ACK 会携带该数据。MCU 无需切换收发模式。
6. 遥控器在后续任务周期调用 `si24r1_get_tx_result()`：PENDING 继续等，SUCCESS 记录成功，FAILED 记录失败。IDLE 不计入统计；ERROR 表示驱动异常，应检查并重新初始化。
7. 飞控调用 `si24r1_receive()` 取出指令，再用 `rcprotocol_parse_control()` 校验。只有解析通过，应用层才更新遥控值和有效帧接收时间。
8. 遥控器调用 `si24r1_receive()` 取出 ACK 数据，再用 `rcprotocol_parse_status()` 更新显示。ACK 本身可以没有应用数据，不能把“没有状态帧”当作“发送失败”。
9. 飞控继续准备新状态，调用 `si24r1_write_ack_payload()`。如果上一份还在等待发送，本次返回 false，保留旧数据，下次任务周期再试。

ACK 数据必须提前装好。飞控 MCU 读取完某个遥控包后才生成的状态，通常由后续遥控包的 ACK 带回，不是对当前操作执行结果的同步确认。驱动不持续塞满三层 ACK FIFO，而只允许一份等待发送的数据，减少排队造成的状态滞后。

## 函数分工

| 接口 | 作用 |
|---|---|
| `si24r1_init()` | 检查 SPI 地址读回，配置无线芯片和角色 |
| `si24r1_set_mode()` | 调试时切换角色；固定角色通信不需要反复调用 |
| `si24r1_send()` | 拷贝载荷到芯片并启动发送，不等待无线 ACK |
| `si24r1_get_tx_result()` | 查询并消费一次发送结果，清理失败的发送队列 |
| `si24r1_receive()` | 每次取一个原始载荷，长度通过指针返回 |
| `si24r1_write_ack_payload()` | 为未来的 ACK 预装一份回传载荷 |

SPI 每次最多交换 33 字节（命令加载荷），使用同步 `HAL_SPI_TransmitReceive()`，单次超时参数 2 ms。SPI 访问本身仍是阻塞的，但不循环等待无线完成或重试；20 ms 是跨调用的无线发送超时判断，不是让 CPU 等待 20 ms。

正常接收只弹出一个载荷，不像旧驱动那样每读完一包就清空整个 RX FIFO。调用者应使用 32 字节缓冲区，重复读取至没有数据。无效长度才清空 RX FIFO。驱动故障后需重新初始化，不在驱动内部自动反复重启设备。

信号格由遥控器统计最近 10 次实际发送结果。失联由飞控根据最后一份有效遥控帧的接收时间判断。SI24R1 驱动不依赖 `remote`、`flight` 或 RTOS，不解析摇杆、不控制电机。
