# 高度估计

[文档索引](README.md)

当前保留两路高度：遥控器继续显示气压相对高度，UART1 对比气压高度与融合高度。融合尚未接入起飞、定高 PID 或电机输出，参数仍需板级验证。

已完成初步静置、抬升、放回及倾斜采集，详见[2026-10-27实测记录](measurements/2026-10-27/README.md)。升降方向得到初步验证；倾斜时仍有假升降，未完成重力补偿验证。用户暂时没有板子，板级工作暂停，保留现有参数。

## 数据流程

1. `sensors_read_baro()` 计算标准海拔，前32次有效读数取均值作为地面零点，之后输出相对高度。BMP280 当前为气压×16、温度×2、IIR4，任务约每50ms读取一次。
2. 传感器任务用六轴姿态将校准后的加速度投影到竖直方向，扣除1g，换算为 m/s²。高度、速度、加速度统一向上为正，静止倾斜时理论竖直加速度仍为零。
3. `Common/height.c` 用加速度预测速度和高度；每个新气压样本只修正一次高度、速度和加速度修正量，形成三阶互补融合。

算法不读取传感器、不调用 RTOS。调用方持有 `height_t` 状态，包含 `height_m`、`velocity_mps` 和 `acc_correction_mps2`。三个接口：

| 接口 | 用途 |
|---|---|
| `height_init()` | 用当前气压高度初始化，速度与加速度修正归零 |
| `height_predict()` | 使用去重力加速度和实际时间间隔积分预测 |
| `height_correct()` | 使用一个新气压高度修正三个状态 |

## 与江科大参考实现的关系

同样使用高度误差反馈修正位置、速度及加速度，参考的是三阶互补思路。新版将计算放在 Common，并按实际时间间隔缩放反馈，不直接照搬参考工程125Hz时的逐次系数。

初始增益按时间常数2秒选取：位置1.5、速度0.75、加速度0.125。气压误差参与修正前限幅±1m，加速度修正限幅±2m/s²。这些是待实测的起点，不表示已完成飞行调参。

预测间隔有效范围为0～20ms（不含零），气压修正间隔为0～200ms（不含零）。传感器任务在IMU样本失效、加速度校准未完成、气压参考未建立、气压超过200ms未成功更新或算法失败时标记融合无效；恢复后等待新的气压及有效姿态重新初始化。不会把旧气压当作500Hz新测量反复修正。

融合提高短期动态估计能力，但仍受加速度零偏、姿态误差和慢速气压漂移影响。它不保证比气压高度在任何情况下都更准确，也不等同于激光离地测距。

## 编译与验证

用户在飞控 `CMakeLists.txt` 的 `target_sources` 中增加 `Common/height.c`；`Common` 已在头文件搜索路径中。此次未修改CMake，也未编译或烧录。

UART1 的气压诊断行新增：`H` 为气压高度（cm），`F` 为融合高度（cm），`Vz` 为融合升降速度（cm/s）。向上为正，融合无效或超过100ms未更新时显示 `----`。遥控器数据包中的 `height_cm` 仍取气压高度，UART2姿态输出保持原样。

先拆桨、不解锁：静置观察 `Vz` 是否接近零，再竖直抬高、保持、放回，检查高度变化与速度符号；另做原地倾斜，排查重力泄漏。记录气压与融合各自的噪声、漂移和延迟，不以一条曲线更平滑就认定可定高。

已完成公式数值检查：匀加速积分、静止倾斜投影、模拟升降、恒定加速度偏差修正、20/50Hz气压更新、非有限值与异常间隔。检查使用提取公式的数值模型，不替代目标编译、任务运行时间和板级验证。
