# DreamFly2 遥控通信协议

本协议用于遥控器 NRF24L01 与飞控 SI24R1 之间的数据传输，与 UART2 匿名上位机协议独立。两端使用相同的 `Common/rcprotocol.c` 和字段约定，协议文件不依赖 HAL、SPI、RTOS 或无线驱动。

## 通用约定

- 帧头为 `0xAB`，类型 `0x01` 表示遥控指令，`0x02` 表示飞控状态。
- 每个无线载荷只放一帧，使用动态载荷长度，按打包函数返回的长度发送，不补齐到 32 字节。
- 多字节整数高字节在前，与旧工程一致；有符号整数按 16 位补码编码。逐字段打包，不直接发送结构体内存。
- 最后一字节是此前所有字节累加后取低 8 位的校验值。
- 长度、帧头、类型或校验不正确时丢弃，解析函数不会修改原输出。
- 这是新版格式，与旧工程不兼容，遥控器和飞控需同步更新。

## 遥控指令：13 字节

| 字节偏移 | 内容 | 说明 |
|---|---|---|
| 0 | 帧头 | `0xAB` |
| 1 | 类型 | `0x01` |
| 2 | 序号 | 每生成一个新的遥控数据包加 1，255 后回到 0 |
| 3～4 | Roll | `uint16_t`，1000～2000，中位 1500 |
| 5～6 | Pitch | `uint16_t`，1000～2000，中位 1500 |
| 7～8 | Yaw | `uint16_t`，1000～2000，中位 1500 |
| 9～10 | Throttle | `uint16_t`，1000～2000，最低 1000 |
| 11 | 按键 | bit0～5 对应按键 1～6，1 表示按下；bit6～7 为 0 |
| 12 | 校验 | 字节 0～11 的累加和低 8 位 |

按键发送消抖后的当前状态，不发送翻转指令。接收端根据新旧状态判断按下事件，重复帧不能重复触发动作；各按键功能由应用层定义。通道超出范围时整帧拒收，不把异常数值强行限幅成有效操作。

## 飞控状态：18 字节

| 字节偏移 | 内容 | 说明 |
|---|---|---|
| 0 | 帧头 | `0xAB` |
| 1 | 类型 | `0x02` |
| 2 | 序号 | 每生成一份新的状态数据加 1，与遥控序号独立 |
| 3 | 状态 | bit0 已解锁；bit1 低电压；bit2 定高开启；bit3 定点开启；其他位为 0 |
| 4～5 | Roll | `int16_t`，角度 × 100；−32768 表示不可用 |
| 6～7 | Pitch | `int16_t`，角度 × 100；−32768 表示不可用 |
| 8～9 | Yaw | `int16_t`，角度 × 100，归一化至 −180～180°；−32768 表示不可用 |
| 10～11 | 电池电压 | `uint16_t`，V × 100，例如 3.85 V 编码为 385；0 表示不可用 |
| 12 | 传感器异常 | bit0 IMU；bit1 磁力计；bit2 气压计；bit3 光流；bit4 测距；1 表示异常，其他位为 0 |
| 13～14 | 油门 | `uint16_t`，飞控接受的遥控油门通道值，1000～2000；不是电机 PWM 或自动定高控制输出 |
| 15～16 | 高度 | `int16_t`，相对地面参考点的高度，单位 cm；有效范围 −32767～32767 cm，−32768 表示不可用 |
| 17 | 校验 | 字节 0～16 的累加和低 8 位 |

未安装的可选传感器不自动视为异常。状态位反映实际状态，不是遥控器发出的请求。

`flags` 可以同时置多个位：`RCPROTOCOL_STATUS_ARMED` 表示已解锁，`RCPROTOCOL_STATUS_LOW_BATTERY` 表示低电压，`RCPROTOCOL_STATUS_ALT_HOLD` 表示定高开启，`RCPROTOCOL_STATUS_POS_HOLD` 表示定点开启。例如已解锁且低电压时为 `0x03`。协议层只传输这些标志，不负责判断电压阈值或切换模式。

有符号姿态／高度字段统一使用 `RCPROTOCOL_INVALID_I16`（−32768）表示不可用，正常零角度和零高度仍编码为 0。高度估计尚未接入时发送该不可用值。应用层负责准备数据，打包函数不读取传感器或控制状态。

### 当前已接入的回传

- 姿态来自六轴解算，保留飞控机体坐标系的符号；只有 UART2 匿名显示做 Pitch/Yaw 方向映射。角度四舍五入为 0.01° 编码，OLED 当前四舍五入显示整数；显示格式不改变通信精度。
- 六轴结果超过 100 ms 未更新时，姿态发送不可用值，并置 IMU 状态位。初始化未完成、IMU 初始化失败或角度不可编码也置该位。
- 系统任务每 100 ms 调用现有电池采样和滑动滤波接口，电压四舍五入为 0.01 V。无线任务只读取快照；超过 500 ms 未更新时发送不可用值 0。底层仍沿用原来的 ADC 轮询实现，此值不额外提供 ADC 转换成功证明。
- MAG、BARO 状态位反映已配置的板载传感器初始化结果，不代表持续运行健康监测；未接入的 FLOW、RANGE 不自动报错。
- 油门仍是接收到的遥控通道值，不是电机输出。ARMED 位反映飞控手势解锁状态；模式切换、定高和起降控制尚未接入。
- 高度来自 BMP280 气压解算：标准海拔减去上电后前32次有效海拔读数的均值，单位由米四舍五入为厘米。读取约20Hz（50ms），初始零点期间、超过200ms未成功更新、非有限数或超出±32767cm时发送−32768。它不是融合高度，地面参考本轮固定，飞行中不持续归零。
- 遥控器失联时隐藏旧姿态和电压。主页面底部出现 `E:xx` 时为传感器状态位的十六进制组合，例如 `E:01` 为 IMU 未就绪／异常，`E:02` 为磁力计初始化失败，`E:04` 为气压计初始化失败。

本次约定不改变控制包 13 字节、状态包 18 字节的长度，但两端需同时更新下载，避免旧飞控的占位零值被新版遥控器当作有效数据。

## 遥控器信号格

信号格可以根据最近一段时间的发送成功率显示，不要求数据包携带序号。江科大遥控器统计最近 10 次发送结果：成功 9～10 次显示 3 格，5～8 次显示 2 格，1～4 次显示 1 格，0 次显示 0 格。发送成功由无线驱动确认收到 ACK，不是回传状态帧中的某个字段，也不是直接测得的射频信号强度。

本协议的序号用于另一类检查：统计接收数据连续性、识别重复数据和观察回传更新情况。发送 ACK 成功率不能代替飞控对有效遥控帧的校验及失联判断。

## 调用与职责

- 遥控器调用 `rcprotocol_pack_control()`，飞控调用 `rcprotocol_parse_control()`。
- 飞控调用 `rcprotocol_pack_status()`，遥控器调用 `rcprotocol_parse_status()`。
- 打包返回帧长，失败返回 0；解析返回 `bool`。
- 物理单位转换、序号递增、按键事件、解锁和失联判断由应用层处理，协议层不操作电机。
- 建议遥控器主动发送，飞控通过 ACK Payload 回传预先准备好的状态。ACK 数据可能来自上一轮，状态序号不能当作当前指令的确认号。
- 序号用于观察丢包和过滤重复数据，不能单独证明连接正常；失联计时应由应用层基于有效、新的遥控帧维护。两端重启或重新连接时需重新建立序号基线，不能简单用数值大小判断新旧。

后续配对、参数交互需要时再增加帧类型。当前格式不承担身份认证；固定无线地址和帧头不能替代配对。


## 无线 IRQ 与任务处理

飞控 PB2（EXTI2）、遥控器 PB3（EXTI3）使用下降沿中断，当前生成配置均已开启 NVIC，优先级为 5，符合两端 FreeRTOS 的系统调用中断优先级限制。本次不修改 Core、Drivers、Middlewares、CubeMX 或 CMake。

两端的 `HAL_GPIO_EXTI_Callback()` 位于各自 `Application/rtos.c`，仅通过 `osThreadFlagsSet()` 通知无线所属任务，不读取 SPI、不解析协议。任务句柄在对应任务启动后、无线初始化前绑定；更早到来的中断被忽略，启动后的首次任务处理会检查状态/FIFO。

- 飞控链路任务在 IRQ 到来时提前唤醒，否则最多等待 5 个系统 tick 后再次检查。处理接收 FIFO，并准备后续 ACK 状态；ACK 发出产生的 TX_DS 也由任务内清理。
- 遥控器控制任务在 IRQ 到来时调用 `remote_process_radio()` 处理发送结果和 ACK 负载；按键、摇杆、校准仍按 5 ms 绝对周期执行，控制包仍最多每 10 ms 启动一次。额外 IRQ 唤醒不加快采样或校准。
- 线程标志自动清除且可以合并。IRQ 在任务工作期间到来时标志会保留到下一次等待，避免先检查、后休眠的竞态；每次仍检查 FIFO，而不把一次中断等同于一包数据。
- 原有周期检查保留，覆盖遗漏下降沿、IRQ 持续低电平、发送超时和数据新鲜度检查。驱动传输故障后的自动重初始化仍未接入。

无线仍为遥控器主发送、飞控主接收加 ACK 负载，不改为空中全双工，也不启用 SPI DMA。全部 SPI 操作仍由各自唯一的任务串行执行。实机验证待完成，未进行编译或烧录。
