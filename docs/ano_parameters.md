# 匿名上位机在线调参

[返回项目首页](../README.md) · [文档索引](README.md) · [Flash 参数保存](flash.md)

飞控通过 UART2 收发匿名 V8 参数报文，支持读取参数列表、读取当前值、修改 RAM 参数、恢复源码默认值和保存 Flash。当前接入的是姿态解算增益，并非电机控制 PID。UART2 已通过脚本发送匿名 V8 报文，实机验证了设备/参数查询、RAM 修改、确认、Flash 保存和掉电加载。匿名上位机界面操作、恢复默认命令和 WiFi 透传尚未实测。

## 连接方式

| 方式 | 连接与设置 |
|---|---|
| USB 转串口 | 飞控 PA2/TX → 转换器 RX，PA3/RX ← 转换器 TX，GND 共地；3.3 V 电平，460800、8N1、无流控 |
| 串口转 WiFi | 模块串口设为 460800、8N1，双向透明传输 UART2 的二进制数据；电脑连接模块实际配置的 TCP/UDP 端点 |

UART1 保留文本调试用途，参数报文走 UART2。更换为 USB 转串口时，应先断开 WiFi 模块对 PA3 的发送连接，避免两个 TX 同时驱动 PA3。WiFi 的串口波特率与 UART2 一致，网络端无需额外封装匿名报文。

当前生成配置已经包含 UART2 收发 DMA 和 USART2 中断。接收使用普通模式 DMA + IDLE 事件，中断只把字节放入接收队列，由调试任务每 20 ms 解析；不需要新增 RTOS 任务。

## 当前参数

| ID | 名称 | 作用 | 源码默认值 | 允许范围 |
|---|---|---|---|---|
| 0 | `ATT6_KP` | 六轴重力方向的比例修正 | 0.8 | 0～20 |
| 1 | `ATT6_KI` | 六轴误差的积分修正 | 0.0003 | 0～5 |
| 2 | `ATT9_KP` | 九轴姿态的比例修正 | 0.2 | 0～20 |
| 3 | `ATT9_KI` | 九轴误差的积分修正 | 0.1 | 0～5 |

四个参数均为浮点型，匿名参数类型为 `8`（`PVT_Float`），值按小端 IEEE 754 float32 传输，不乘 1000。范围只是输入检查边界，并非建议调参范围。启动时优先加载有效 Flash 记录，因此上位机读到的值可能与源码默认值不同。

## 操作流程

1. 编译、下载更新后的飞控程序，等待初始化结束，保持飞控上锁、停桨。
2. 在上位机连接 UART2 或 WiFi，读取设备信息及参数列表，应看到 `DreamFly2` 和上述四个参数。
3. 修改一个参数后，重新读取当前值确认。修改先在 RAM 生效，传感器任务在两次姿态解算之间应用增益；保留当前姿态，清空算法的积分修正历史。应用成功才回确认。
4. “恢复默认”只恢复源码默认值到 RAM；要掉电保留，仍需再执行“保存”。
5. 执行“保存”后，飞控将当前四个参数写入 Flash 并比对，成功才回确认。再重启并读取参数，验证掉电保存。

解锁状态下拒绝修改、恢复默认和保存，仍可读取。拒绝或失败时发送 `0xA0` 文本日志，不发送成功确认；上位机可能显示操作超时。保存可能暂停采样和通信，停桨后再操作。重复保存相同内容会直接返回成功，避免重复擦除。

## 报文约定

沿用当前项目设备地址 `0x66`，上位机通常为 `0xFE`，广播地址 `0xFF`。自动发现可使用广播，定向命令目标需为 `0x66`。回复发往请求来源。若所用上位机固定了其他设备地址，需按实际抓到的报文核对。

| 请求 | 内容 | 回复 |
|---|---|---|
| `0xE0`，命令 `0x00` | 设备信息 | `0xE3` |
| `0xE0`，命令 `0x01` | 参数数量 | `0xE0`，数量为 4 |
| `0xE0`，命令 `0x02 + ID(u16)` | 当前参数值 | `0xE1` |
| `0xE0`，命令 `0x03 + ID(u16)` | 类型、范围、名称及描述 | `0xE2` |
| `0xE1`，`ID(u16) + 值(float32)` | 修改参数 | 成功后 `0x00` 确认 |
| `0xE0`，`0x10 + 0x00AA(u16)` | 恢复源码默认值到 RAM | 成功后 `0x00` 确认 |
| `0xE0`，`0x10 + 0x00AB(u16)` | 保存当前参数到 Flash | 成功后 `0x00` 确认 |

多字节字段小端排列，SC/AC 校验从 `0xAB` 帧头开始计算。确认帧数据为原请求的 `[帧 ID, SC, AC]`。接收支持分段、连续多帧、坏帧重同步；响应优先于周期姿态发送。

## 代码位置

- `Common/anoprotocol.c/.h`：通用打包、校验和帧解析，不依赖串口。
- `Application/debug.c/.h`：UART2 DMA 接收队列和发送。
- `Application/flight.c/.h`：参数表、命令处理、应用增益和 Flash 保存。
- `Application/rtos.c`：沿用调试任务调用入口。

增加参数时同步修改参数结构体、默认值、范围检查、参数表及 Flash 记录版本/长度检查；当前持久化格式明确限定为四个浮点增益。

## UART2 实机记录（2026-10-28）

使用 ST-Link 虚拟串口连接 UART2，460800、8N1，通过测试脚本直接收发匿名 V8 报文；串口已释放，可交由上位机打开。

| 项目 | 实测结果 |
|---|---|
| 周期姿态输出 | 收到有效 `0x03` 帧，SC/AC 校验通过 |
| 设备查询 | 返回 `DreamFly2`，参数数量为 4 |
| 参数信息与数值查询 | 四项名称、浮点类型、范围和当前值均正确 |
| 在线修改 | `ATT6_KP` 从 0.8 改为 0.801，收到匹配的确认帧，回读的浮点字节完全一致 |
| 原值恢复 | 恢复为 0.8，精确回读通过 |
| Flash 保存 | 收到匹配的保存成功确认 |
| 掉电加载 | 再临时保存 0.801，用户完全断电重启后读回仍为 0.801，区别于源码默认值 0.8 |
| 测试收尾 | 四个参数已精确恢复到测试前值，并收到重新保存成功确认 |

最终保存值：六轴 `KP=0.8`、`KI=0.0003`，九轴 `KP=0.2`、`KI=0.1`。测试没有编译或烧录固件，没有改动底层配置。

此记录证明 UART2 协议收发及参数持久化链路可用；不等同于已验证匿名上位机界面兼容性、WiFi 网络配置、恢复默认命令、解锁拒绝分支或调参后的姿态性能。
